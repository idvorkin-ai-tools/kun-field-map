Voice, video and toys

Ten smaller repos, each one a single job with an agent in the loop, read from their own READMEs.
Sourcegithub.com/kunchenguid ↗
TL;DR — Around the main agent tooling sits a shelf of side builds. Three of them handle video: recording (justroll), cutting by transcript (rough-cut-axi) and turning long talks into vertical shorts (short-pipe). Two keep a human in control of an agent: m87 only acts on your GitHub inbox after you approve, and baby-menu lets you keep or undo every change the agent makes to it. autopreso turns speech into a live whiteboard. trial-by-combat and fly-with-me are toys, and runner-up and headless set up the machines underneath. Most are young, and several are macOS-only.

These repos are small, but they share a habit. Each README opens with one specific annoyance, then hands the tedious part to an agent and keeps the decisions with you. This page gives each tool a short section: the idea, how it works, and where it stops.

autopreso: the whiteboard draws itself

autopreso starts from the fact that you wanted to give the talk, not build the slides. It runs a local web app with an Excalidraw canvas. Your microphone feeds a speech-to-text engine: Moonshine on the machine, or OpenAI's Realtime API. The transcript streams to a model, and the model edits the scene through tool calls, adding boxes, labels and arrows as you speak. You set up the start by hand in a "staging" mode with a title, an agenda and a few seed shapes. Then "live" mode hands the canvas to the agent, which warms up on your staging content so it isn't starting cold on your first sentence.

npx autopreso     # serves on 127.0.0.1:3210 and opens the browser

You bring the model: an OpenAI key, a Codex subscription, or Ollama for a fully local setup. The server listens only on localhost. The README labels it alpha and warns about "the occasional weird drawing". The local transcription sidecar only ships for macOS.

In use: autopreso was tried in Larry's setup as a voice-driven whiteboard.

The video chain: justroll, rough-cut-axi, short-pipe

justroll deals with recording a talking-head video across several screens. Normally you'd juggle OBS scenes, or forget the second display. justroll is one terminal command that opens a wizard: pick a mic, the screens and a camera, and it records each source to its own file. Nothing is mixed into one frame. Lining the files up afterwards relies on a small trick:

the same mic is muxed into every clip, so any editor's "synchronize by audio" lines them up.justroll README

It is open about macOS quirks. All screens share one ffmpeg process, because two separate screen captures hang the system. It records to MKV so a crash doesn't wreck the file, then converts to MP4 when you stop. It needs macOS, Node 20 and ffmpeg.

rough-cut-axi is a video editor where the transcript is the timeline. You open your footage and it gets transcribed (by ElevenLabs, so that step is not local). The browser editor shows the transcript as prose, and you mark passages to keep or skip. The original footage is never modified. The project is a pair of plain files: project.json is what the editor shows, and timeline.json is what gets rendered. It is an AXI tool (the agent-first CLI style from earlier pages), so an agent can join the edit. poll waits for feedback you leave in the browser, snapshot prints the project compactly, and apply validates JSON edit operations. A plan with more than three operations needs --approved. Rendering runs through ffmpeg.

short-pipe is a desktop app for the next step. Give it a long video and it transcribes it locally with Whisper, word by word. An agent reads the transcript and proposes ranked soundbites, following a skill bundled in the repo. You approve and trim each one on a waveform, pick a layout and caption style, and it renders 1080×1920 clips on your machine. The agent runs on your Codex subscription. The README calls it an MVP: macOS only, and builds are not notarized, so the first launch needs right-click → Open.

The pattern, and how sure we can be. None of the three READMEs mentions the others. justroll hands off to "your editor", and short-pipe accepts any long video. Still, the shapes match, and his channel gives some evidence. On 2026-06-05 he posted Shorts such as Interest rate and layoffs, and their transcripts follow passages from his long video of 2026-05-21, AI tech layoffs explained, around the 2:31 mark. The short-pipe repo was created on 2026-06-04. Together that suggests he records a long talking-head video and cuts it into Shorts with his own tools. It does not prove which tool made which clip.

m87: the agent recommends, you ship

If you let an agent loose on your issues and pull requests, it ends up commenting, closing and merging on your behalf while you aren't looking. m87 splits the job in two. A local background process syncs GitHub, an agent reads each item and recommends an action, and the recommendation waits in a queue:

Nothing source-visible happens until you review the exact outgoing action and explicitly approve it.m87 README

The approval gate is concrete. m87 preview (or the "WILL DO" panel in the terminal inbox) shows the exact effect. Approving needs --confirm, and destructive actions need --confirm-destructive. If you approve a fix, a coding agent opens a draft PR, and m87 never merges it. The agent is reached over ACP (Agent Client Protocol, a standard way for a tool to drive a coding agent such as claude, codex or opencode, which m87 detects). All state lives in SQLite under ~/.m87, with no hosted backend.

npm install -g @kunchenguid/m87
m87 init            # guided setup: agent, GitHub repos, run at login?
m87                 # live inbox: pick an option, read WILL DO, press a

baby-menu: software that edits itself

Menu-bar apps come with a fixed set of widgets. baby-menu has your agent write new ones instead:

You ask for a feature in plain English, the agent writes an extension and it hot reloads into the menu in real time.baby-menu README

What makes it safe is the Keep / Undo bar. The agent writes widget and layout files under ~/.baby-menu/extensions, and after each turn the app reads the actual git or snapshot diff. It labels the change from that diff, not from what the agent says it did, and you keep the turn or throw it away. Bundled "recipes" are short specs that tell the agent how to read real data sources, such as Claude Code or Codex quota, and to check the finished widget against that data. In a July video he shows a baby-menu widget tracking his own quotas. It needs macOS 13 or newer and an agent CLI that is already signed in.

Toys: trial-by-combat and fly-with-me

trial-by-combat is a reply to benchmarks nobody wants to watch. Two LLM agents play Capture the Relic on a 9×9 grid. Both move at the same time, bushes, scans and traps hide information, and there is no randomness inside a match, so the same moves always give the same result and replays are exact. Agents play over plain-text HTTP. Every response contains the briefing, the grid and the exact curl to run next, so the agent needs no client library. Every action must carry an intent field saying why.

fly-with-me has no agent at all. It is a browser page where a bird flies across an endless generated world, with sound synthesized in the browser. Open it and press Begin. Leave it alone and the bird flies itself, or drag to steer. A ?seed= parameter reopens the same world. It uses WebGPU where available and falls back to WebGL2.

Infra side builds: runner-up and headless

runner-up runs GitHub Actions jobs on machines you already own. One coordinator subscribes to GitHub's runner scale sets and starts a one-job runner on a free "place". A place is a fresh Docker container or KVM VM on Linux, a tart clone or Apple container on a Mac, or an account or Hyper-V VM on Windows, and it is removed when the job ends. Jobs from forked repos are refused by default. The README is candid: it calls the project "young", notes that scale sets are still a GitHub preview, and marks several place types experimental. Docker places share the host kernel, and "host" places aren't fresh at all, so use them only for code you trust.

headless is an Agent Skill (an instruction bundle an agent loads on demand) that turns a machine with a password-protected admin account into one that never sleeps, signs itself in after a restart, accepts only SSH keys, and can join Tailscale. The key design choice is that the admin password stays in your secret store (1Password, Bitwarden, or any command). The agent only names the entry, and the scripts pipe the password through without it appearing on a command line or in a log. Each step can be rerun safely, and the final step reads every setting back and restarts the machine to check. Installing NixOS on a Linux box erases the disk, and the README says so.

npx skills add kunchenguid/headless -g
/headless set up my Mac mini at 192.168.1.20 as a headless machine
